# TaskFlow — data refresh contract

`taskflow/index.html` is a static viewer. Everything it shows comes from `data/taskflow.js`,
which is regenerated by a **scheduled Claude Code session** with the Microsoft 365 connector.
Claude Code is the backend: it does the Outlook pull and the deal-sheet research at refresh
time, then pushes a plain data file. The page needs no API key, no server, and no
network access beyond GitHub Pages.

```
   Outlook / Teams ──► scheduled Claude Code session ──► data/taskflow.js ──► git push
                                                                                  │
                                                     GitHub Pages ◄───────────────┘
                                                          │
                                        your browser ─────┴──► + your local edits
```

## The rules

Repo-wide working conventions live in **[CLAUDE.md](CLAUDE.md)** — read it first. The one that
bites hardest on a refresh: **always combine like items.** Merge a new task into an existing one
when it is the same workstream, keeping the oldest id, rather than appending a near-duplicate.

**Never edit `taskflow/index.html` during a data refresh.** Only `data/taskflow.js` changes.
If the viewer genuinely needs a change, that is a separate commit.

## Why ids matter

The site keeps your completions, added tasks and deletions in `localStorage`, keyed by **id**. A refresh rewrites the dataset underneath that overlay, so:

| Rule | Why |
|---|---|
| Reuse the existing id for an item that already exists | Otherwise your "done" tick detaches and the task comes back open |
| Never recycle an id for a different item | The old item's status would silently transfer to the new one |
| Keep carried-over ids byte-identical (`s-ash13`, `t-aus20`, …) | Same reason |
| It is fine to drop an item from the dataset | It just disappears; the overlay entry becomes inert |
| Ids the user deleted locally never come back | The viewer filters them out even if you re-add them |

New items get a fresh prefix: `t-<proj><n>` for tasks found in mail, `ev-<mmdd>-<n>` for calendar
events.

## The refresh prompt

Paste this into a Claude Code session on this repo (or let the scheduled Routine fire it):

> Refresh `data/taskflow.js` for the TaskFlow desk site.
>
> 1. **Calendar** — pull my Outlook calendar for today through 14 days out. Store instants as UTC
>    (`startUtc`/`endUtc` with a trailing `Z`); Graph returns this mailbox with `timeZone: "UTC"`,
>    so its wall-clock string already *is* UTC — do not shift it. Set `allDay` and `tentative`
>    (`showAs === "tentative"`). Give each event a `tag` from the existing palette
>    (austin, ashville, scioto, canyon, leroy, enigma, liverpool, internal, market, social, location).
>    All-day location holds ("Denver", "Virginia") use `tag: "location"`.
> 2. **Project meta** — keep `projectMeta` current: stage, size, financing type and
>    counterparties per deal, plus a `typeShort` (a few words) for the table cell,
>    with the full `type` reserved for the hover tooltip. Every field must be SOURCED — add the reference to that project's
>    `sources` array. If you cannot evidence a figure, leave it `""` so the page renders "not
>    captured"; never estimate a deal size. Do NOT store workstreams here — the page derives them
>    from open tasks so the table cannot drift from the board.
> 3. **New deals** — when a codename shows up in the mail or calendar that has no entry, add both
>    a `projects` row and a `projectMeta` row for it rather than filing its tasks under an
>    existing deal.
> 4. **Merge before you add** — for each candidate new task, check the project's existing tasks
>    first and MERGE if it is the same workstream (same counterparty and artefact, two directions
>    of one exchange, a task and its own follow-up step). Keep the oldest id so the user's
>    completions stay attached, fold both descriptions into `notes`, record the retired id in
>    `source`, and take the earlier due date and higher priority. See CLAUDE.md for the full rule.
> 5. **Tasks** — carry the existing backlog forward by id. Give every task a
>    `summary` and a `group`. The summary is what shows on the board: write the
>    POINT of the item in under ~55 characters ("Waiting on Laura's review before
>    it can go out"), not the opening words of the note clipped short — the
>    viewer falls back to mechanical truncation only when `summary` is missing,
>    and it reads badly. `group` is the workstream heading within the project;
>    reuse the names already in use rather than inventing near-duplicates. Update `notes`/`due` where the mail
>    moved something. Add tasks for genuinely new commitments found in mail, with a `source`
>    naming the message. Do not silently delete backlog items; if something looks done, add it to
>    `taskUpdates` with `status: "Done"` and bump `updateBatch`.
> 6. Update `meta.as_of`, `meta.generated_at`, `meta.windows` and `meta.sources`, keep
>    `meta.notes` honest about anything you could not verify.
> 7. Render-test the page (see below), rebuild and republish the shareable artifact to the
>    existing URL, then commit and push — including `dist/`.

## Publishing the shareable page

The GitHub Pages copy picks up a refresh automatically — it reads `data/taskflow.js` at load.
The **published artifact does not**: its data is baked in, so it has to be rebuilt and
republished after each refresh.

```bash
node tools/build-standalone.js     # -> dist/taskflow-standalone.html
```

Then republish that file to the existing artifact, passing the URL so it updates in place
instead of minting a new one:

```
ARTIFACT_URL = https://claude.ai/code/artifact/16badd5b-3770-4fc1-8ff2-4d65c1f261f9

Artifact(
  file_path: "dist/taskflow-standalone.html",
  url:       ARTIFACT_URL,
  label:     "data 2026-08-10",     # always: "data <meta.as_of>"
  favicon:   "📋"                    # keep stable — the tab icon identifies the page
)
```

Passing `url` is what keeps the link the user has already shared working. A session that
did not itself publish the artifact will otherwise create a brand-new URL.

### Where versions live

| | Kept where | How to get back to one |
|---|---|---|
| **Cloud** | Artifact version picker, one labelled entry per republish | Pick the label on the artifact page |
| **Local** | `git` — `dist/taskflow-standalone.html` is committed each refresh | `git log -- dist/` then check out the commit |

Commit `dist/` on every refresh. It is generated, but committing it is the point: it leaves a
diffable local record of exactly what was published, matched to the dataset that produced it.

## Render test

The site is plain HTML + one data file, so a real browser check is cheap and catches
a malformed dataset immediately:

```bash
python3 -m http.server 8817 &          # from the repo root
# then load http://127.0.0.1:8817/taskflow/index.html
```

Confirm: no console errors, the KPI row has real numbers, the calendar month renders with
today highlighted, and the Projects table expands a detail row when clicked. A JS syntax error in `data/taskflow.js`
shows as a completely empty page — check the console first if that happens.

## Scheduling it

Create a Routine that fires a fresh session each weekday morning with the prompt above.
Weekday 6:00 AM MT is 12:00 UTC (13:00 UTC during MST):

```
create_trigger(
  name: "TaskFlow morning refresh",
  cron_expression: "0 12 * * 1-5",
  create_new_session_on_fire: true,
  prompt: "<the refresh prompt above, verbatim>"
)
```

Because each firing starts from nothing, the prompt has to be self-contained — that is why it
restates the repo, the file, and the id rules rather than assuming prior context.

## Known limits

- **The Microsoft 365 connector is read-only** — search and read, no move/update/delete. Nothing
  in this repo can change the mailbox or the calendar.
- **Deal sizes are mostly missing.** 6 of 8 deals have no size on file because none of the
  sources read so far state one. Leave them blank; a traceable gap beats an untraceable number.
  Sizes for closed facilities can be cross-read from `data/data.js` (the Q2 2026 commitments
  extract behind the Bank Conversation Dashboard).
- Searches cover the messages they return, not the whole mailbox. When the window is busy, say so
  in `meta.notes` rather than implying full coverage.
- Two features were built and then shelved: **inbox triage with draft replies**, and the
  **Outlook cleanup** tab. Cleanup is preserved with restore notes under
  `archive/outlook-cleanup/`; the triage version is in git history (`git log -- data/taskflow.js`).
- Calendar invites that get rescheduled by email but not reissued will show the stale hold.
  That is a real signal, not a bug — flag the drift in the inbox `why` when you spot it.
- `localStorage` is per browser and per device. A completion ticked on your laptop does not
  show on your phone.
