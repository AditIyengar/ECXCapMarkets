# TaskFlow — data refresh contract

`taskflow/index.html` is a static viewer. Everything it shows comes from `data/taskflow.js`,
which is regenerated by a **scheduled Claude Code session** with the Microsoft 365 connector.
Claude Code is the backend: it does the Outlook pull, the inbox triage, and the draft-writing
at refresh time, then pushes a plain data file. The page needs no API key, no server, and no
network access beyond GitHub Pages.

```
   Outlook / Teams ──► scheduled Claude Code session ──► data/taskflow.js ──► git push
                                                                                  │
                                                     GitHub Pages ◄───────────────┘
                                                          │
                                        your browser ─────┴──► + your local edits
```

## The one rule

**Never edit `taskflow/index.html` during a data refresh.** Only `data/taskflow.js` changes.
If the viewer genuinely needs a change, that is a separate commit.

## Why ids matter

The site keeps your completions, added tasks, deletions, edited drafts and handled-mail flags in
`localStorage`, keyed by **id**. A refresh rewrites the dataset underneath that overlay, so:

| Rule | Why |
|---|---|
| Reuse the existing id for an item that already exists | Otherwise your "done" tick detaches and the task comes back open |
| Never recycle an id for a different item | The old item's status would silently transfer to the new one |
| Keep carried-over ids byte-identical (`s-ash13`, `t-aus20`, …) | Same reason |
| It is fine to drop an item from the dataset | It just disappears; the overlay entry becomes inert |
| Ids the user deleted locally never come back | The viewer filters them out even if you re-add them |

New items get a fresh prefix: `t-<proj><n>` for tasks found in mail, `in-<slug>` for inbox
entries, `ev-<mmdd>-<n>` for calendar events.

## The refresh prompt

Paste this into a Claude Code session on this repo (or let the scheduled Routine fire it):

> Refresh `data/taskflow.js` for the TaskFlow desk site.
>
> 1. **Calendar** — pull my Outlook calendar for today through 14 days out. Store instants as UTC
>    (`startUtc`/`endUtc` with a trailing `Z`); Graph returns this mailbox with `timeZone: "UTC"`,
>    so its wall-clock string already *is* UTC — do not shift it. Set `allDay` and `tentative`
>    (`showAs === "tentative"`). Give each event a `tag` from the existing palette
>    (austin, ashville, scioto, canyon, leroy, enigma, liverpool, internal, market, social, location).
>    All-day location holds ("Denver", "Virginia") use `tag: "location"`.
> 2. **Inbox** — read my Inbox for the last 4 days and triage into four buckets:
>    - `reply` — someone asked *me* a direct question, or tagged me by name with an ask
>    - `action` — something for me to do or read; no reply owed
>    - `waiting` — I'm owed something by someone else
>    - `fyi` — read/skim only
>    Write a one-sentence `why` for each explaining the bucket. **Group high-volume noise**
>    (PM status forwards, bank market updates) into a single entry rather than one per message.
> 3. **Drafts** — for every `reply` item, write a `draft`: short, professional, first person,
>    under ~80 words, matching my house style (greeting, the substantive answer, a commitment
>    with a timeframe, "Best,\nAditya"). Never invent a fact I haven't stated — if the answer
>    depends on something unknown, commit to coming back on it instead of guessing.
> 4. **Tasks** — carry the existing backlog forward by id. Update `notes`/`due` where the mail
>    moved something. Add tasks for genuinely new commitments found in mail, with a `source`
>    naming the message. Do not silently delete backlog items; if something looks done, add it to
>    `taskUpdates` with `status: "Done"` and bump `updateBatch`.
> 5. Update `meta.as_of`, `meta.generated_at`, `meta.windows` and `meta.sources`, keep
>    `meta.notes` honest about anything you could not verify.
> 6. Render-test the page before pushing (see below), then commit and push.

## Render test

The site is plain HTML + one data file, so a real browser check is cheap and catches
a malformed dataset immediately:

```bash
python3 -m http.server 8817 &          # from the repo root
# then load http://127.0.0.1:8817/taskflow/index.html
```

Confirm: no console errors, the KPI row has real numbers, the calendar month renders with
today highlighted, and each inbox bucket has items. A JS syntax error in `data/taskflow.js`
shows as a completely empty page — check the console first if that happens.

## Scheduling it

Create a Routine that fires a fresh session each weekday morning with the prompt above.
Weekday 6:00 AM MT is 12:00 UTC (13:00 UTC during MST):

```
create_trigger(
  name: "TaskFlow morning refresh",
  cron_expression: "0 12 * * 1-5",
  create_new_session_on_fire: true,
  prompt: "<the refresh prompt above, verbatim>"
)
```

Because each firing starts from nothing, the prompt has to be self-contained — that is why it
restates the repo, the file, and the id rules rather than assuming prior context.

## Known limits

- Triage covers the messages the search returns, not the whole mailbox. When the window is busy,
  say so in `meta.notes` rather than implying full coverage.
- Drafts are suggestions. Nothing is ever sent from the page; you copy into Outlook and send.
- Calendar invites that get rescheduled by email but not reissued will show the stale hold.
  That is a real signal, not a bug — flag the drift in the inbox `why` when you spot it.
- `localStorage` is per browser and per device. A completion ticked on your laptop does not
  show on your phone.
